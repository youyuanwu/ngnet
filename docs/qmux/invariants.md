# QMux invariants

The properties the QMux suite pins rather than merely exercises, and where each is enforced.
A test that would still pass if the property were broken is not on this list.

## Enforced by the compiler

These are `compile_fail` doctests in `crates/ngnet-qmux/src/compile_fail.rs`. A runtime test
cannot express "this cannot be written", and each of these claims is about something the API
makes impossible rather than something it rejects.

| Property | Why it matters |
| --- | --- |
| **A handler cannot name the connection it belongs to** | This is the entire mechanism behind dwnx's rule that `dwnx_conn_writev_stream` must not be called from inside a callback, and behind the callback bridge's inability to survive a nested entry point. Two cases are pinned: capturing a connection into a handler, and using one from inside a handler installed on it. |
| **`Conn` is not `Sync`** | The bridge slot is written on every entry point without synchronisation. That is sound only because those entry points take `&mut self`; sharing a connection between threads would break it. `Conn` is `Send`, which a positive assertion in `tests/lifecycle.rs` pins. |
| **The record buffer cannot be touched mid-record** | dwnx retains the `dest` pointer for the whole `WRITE_MORE` sequence. `RecordWriter` borrows the buffer for its own lifetime so that swapping or mutating it partway through does not compile. Without this the API would admit a use-after-free from safe code. |
| **A handler must be `Send`** | `Conn` carries a hand-written `unsafe impl Send` and owns its handlers, so a non-`Send` capture would let safe code move an `Rc` across threads and race its refcount. |

## Enforced against the C library

These read the vendored sources or call into the built archive, so they fail when upstream
moves rather than when this crate does.

| Property | Where |
| --- | --- |
| **Every `DWNX_ERR_*` condition is classified, and classified correctly** | `crates/ngnet-qmux/tests/error_mapping.rs` scans `deps/dwnx/lib/includes/dwnx/dwnx.h` for the constants rather than listing them. A hand-written list would pass forever: adding a twenty-fifth `#define` upstream would not make it fail, which is exactly the regression worth catching when the submodule moves. The check runs both ways, so a constant removed upstream also fails. `DWNX_ERR_FATAL` is excluded as the threshold rather than a condition. The expected `ErrorKind` for each is asserted too, not merely listed: checking only that a constant appears would prove the mapping total while saying nothing about whether it is right. |
| **The restated macros match the header** | `crates/ngnet-qmux-sys/wrapper.h` restates the five time units and the varint bound, each pinned by a `_Static_assert` against dwnx's own definition. bindgen silently drops these macros because they are written with a cast, so the restatement is necessary; the assertion is what stops it drifting. Their Rust widths are pinned separately in `tests/smoke.rs`, because bindgen sizes each constant to its literal rather than to `dwnx_duration`. |
| **Every public dwnx function is reachable** | `crates/ngnet-qmux-sys/tests/smoke.rs` names all 33. Without this, an allowlist regression surfaces as a confusing error inside the safe crate rather than in the crate that owns the bindings. |
| **Struct layout agrees with the C compiler** | The same file constructs and frees a real connection in each role. dwnx reads `callbacks`, `settings` and `params` through pointers the C compiler laid out; a field offset bindgen disagreed about would produce garbage or a crash here. |
| **The stream-id encoding agrees with dwnx** | `crates/ngnet-qmux/src/stream.rs` decodes the initiator and directionality from the low bits without an FFI call, and a unit test compares its answer against `dwnx_is_bidi_stream` across a range of ids. Deriving locally is only worth doing if it is right. |
| **The C defaults are reproduced, not improved upon** | `crates/ngnet-qmux/src/params.rs` and `settings.rs` seed from `dwnx_transport_params_default` and `dwnx_settings_default`, and tests assert the results field by field — including that every flow-control and stream limit is zero. `ngnet-quic` overlays its own working values on ngtcp2's zeros; this crate does not, so "the defaults" means the library's. |

## Enforced about the wrapper's own behaviour

| Property | Where |
| --- | --- |
| **Parameters that would abort are rejected before reaching C** | `crates/ngnet-qmux/tests/lifecycle.rs`. dwnx guards its constructor preconditions with `assert`, so an out-of-range limit aborts rather than failing. Each rejection asserts `error.native().is_none()`, which is what proves the check happened on the Rust side rather than being a C error rendered nicely. |
| **The C defaults still construct** | The same file. The validation above must not overreach: dwnx accepts its own zero-limit defaults, so the wrapper must too, however useless the resulting connection is until limits are raised. |
| **A handler's error message survives the round trip** | `crates/ngnet-qmux/tests/events.rs`. dwnx collapses every nonzero callback return to `DWNX_ERR_CALLBACK_FAILURE`, so the test asserts on the caller's own message, not merely on the error kind — the kind alone would pass with the message lost. |
| **Handler state drops exactly once** | `crates/ngnet-qmux/tests/lifecycle.rs` counts drops of a sentinel captured by a handler. The connection frees the C object and several boxes; this is what would catch a leak or a double drop of the Rust side. Construction and drop are also repeated 512 times. |
| **An abandoned record does not poison the next one** | `crates/ngnet-qmux/tests/events.rs`. `RecordWriter::drop` finalises an unfinished record, without which dwnx would keep appending through a pointer into a freed buffer. A companion test pins the other half — that abandoning a record which took stream data loses those bytes and desynchronises the stream — so the hazard is documented rather than discovered. |
| **A moved connection still works** | The same file. dwnx holds the address of the boxed bridge slot for the life of the connection, which is the reason it is boxed at all. Moving the `Conn` and then using it is what makes that reasoning testable. |
| **All twelve protocol events reach a Rust closure** | `crates/ngnet-qmux/tests/events.rs` drives one connection pair through a sequence that fires each. Grouped into a single test because they need that shared sequence; split apart, each would rebuild it. |
| **A peer close is an outcome, not a failure** | The same file. dwnx reports it as `DWNX_ERR_DRAINING`, which is easy to mistake for an error. The test builds a CONNECTION_CLOSE record by hand, because dwnx parses them but exposes no way to serialise one. |
| **The six write outcomes are distinguishable** | `tests/events.rs` and `tests/transfer.rs` between them produce a completed record, an idle connection, `WRITE_MORE`, a flow-control-blocked stream, a closed write side, and a too-small buffer. The last is the one that would otherwise be indistinguishable from idle, since dwnx answers `0` for both. |
| **Records may be split across reads arbitrarily** | `crates/ngnet-qmux/tests/transfer.rs` runs the same transfer twice, once in bulk and once feeding a single byte at a time, and requires identical observed events. A real transport does not preserve write boundaries, so this is not a synthetic case. |

## Enforced about the asynchronous layer

In `crates/ngnet-qmux/tests/io_*.rs`. These are behavioural, and each one names the test that
fails when the property is lost — not the test that would merely become slower or uglier.

| Property | Where |
| --- | --- |
| **Records reach the byte stream whole, unduplicated and in order, however a write stops** | `io_lifecycle.rs`, `a_backed_up_transport_does_not_lose_a_record`, against a byte stream that accepts one byte per call — the least generous transport a connection can be handed. It used to pin a stronger rule, that a record reached the byte stream in full before the next was produced; coalescing overturned that rule deliberately (see `design.md`, "Produce up to the ceiling, write once, then read"), so the test now queues several records before letting any of them out and asserts that all of them arrive whole, once each, in order. That is the pair of failures a partial accept invites — resuming from the wrong offset, and resending what was already taken — and a partial accept can now stop *inside* a record, which is the case the one-record rule made unreachable and this test exists to reach. `io_transfer.rs`'s `a_transfer_survives_one_byte_per_call` is the same discipline over a whole exchange, and `io_writes.rs`'s `a_slow_consumer_does_not_push_the_buffer_past_the_ceiling` is the memory consequence, which is now a stated bound rather than an implied one and is therefore measured rather than argued. |
| **Buffered operations retain only under an explicit later-flush obligation** | `io_writes.rs`'s `buffered_event_and_open_calls_owe_one_forced_flush` proves retention and later forced visibility; its ceiling tests prove capacity remains bounded. `io_scheduling.rs`'s `a_byte_stream_that_cannot_proceed_at_first_still_completes_a_transfer` covers `Written::NotNow`; `io_writes.rs`'s `a_byte_stream_that_accepts_nothing_is_woken_rather_than_stalled` covers forbidden zero acceptance; and the short-acceptance offset cases live in `io_writes.rs` and `io_vectored.rs`. |
| **A short accept from `try_write_stream` is a bound, never a record boundary** | `io_writes.rs`, `one_offer_fills_the_buffer_rather_than_a_single_record`. One call fills records until the peer's window or the outbound ceiling stops it, and the test's second assertion is the load-bearing one: the offer that answered short is followed by one that is refused outright, which is what says the first stopped at a bound. The property matters because the HTTP/3 layer above is told a count and nothing else, and it reads a short count as congestion and stands the stream down for the rest of its pass — so a call that stopped at a record boundary would cost that stream the rest of the pass for no reason. `tests/ngnet-qmux-h3-tests/tests/driver_writes.rs` is the same property observed as write counts at the driver, where it is worth 28 writes against 130 for a 2 MiB body. |
| **Fragments of one payload share records, and a resumption walks them against a total** | `io_vectored.rs`. `fragments_that_fit_inside_one_record_become_one_record` is the claim in its smallest form; `fragments_beyond_one_record_cost_no_more_records_than_the_same_bytes_contiguous` is the general one, and it is stated as a comparison against the same bytes sent as a single slice rather than against an arithmetic minimum, because computing the minimum would be a second implementation of dwnx's framing that agreed with the test and with nothing else. The load-bearing one is `a_take_that_stops_inside_a_fragment_resumes_inside_it`: `*pdatalen` is one total across every vector rather than a count per vector, so a short take routinely stops part-way through a fragment, and a walk that assumed whole fragments were taken would send some bytes twice and others never while reporting a count that agreed with itself — there is nothing above to disagree with it. `a_list_longer_than_one_push_still_ends_the_stream_after_its_last_fragment` covers the case where the list is longer than the sixteen-entry array one push submits, where the end-of-stream marker must be withheld from the push that leaves fragments behind. `a_lender_may_invalidate_its_fragments_as_soon_as_the_call_returns` is the safety half: dwnx copies the vectors during the call and retains only the destination, which is what lets `ngnet-qmux-h3` declare `RETAINS_BUFFERS = false`. What the packing is worth is a record count and not a time, and `tests/ngnet-qmux-h3-tests/tests/fragmented_offers.rs` says why. |
| **A partial write reports what it took, even when it then refuses** | `io_streams.rs`, `a_partly_taken_write_reports_what_it_took_even_when_it_then_blocks`, with a window deliberately not a multiple of the offer size so the boundary falls partway through a write. It asserts both halves: that the sender counts exactly the window's worth, and that the peer receives exactly those bytes. A count dropped because the same record also reported a block is a byte the caller sends twice, and the peer reads a duplicated fragment inside a frame it was told the length of — a protocol failure some distance from its cause. This is a regression test; the bug was real. |
| **A stream that is gone is a closed stream, not a dead connection** | `io_streams.rs`, `writing_to_a_stream_that_is_gone_is_reported_rather_than_fatal`, which finishes the stream from both ends and then writes to it. The exemption in the production path is conditional on nothing having been packed yet, which is what keeps it from swallowing a genuine failure: any other push error latches an ending, and `io_lifecycle.rs`'s `an_ended_connection_reports_the_same_ending_again` pins that a latched ending is reproduced rather than retried. Nothing induces a genuine push error, because from a safe API there is no way to make dwnx fail one — that half rests on the code path, not on a test. |
| **The framer latches a close permanently rather than keeping a sliding window** | `io_framing.rs`. `a_close_followed_by_trailing_bytes_in_the_same_read_survives` is the case a window loses, and it is not synthetic: a peer may write its close behind whatever was already queued, and a byte stream may deliver both in one chunk. `the_first_close_is_the_one_kept` pins the direction of the latch, `a_close_behind_another_frame_in_its_record_is_latched` pins that the scan does not assume the close is first, and `retention_never_exceeds_one_record_in_progress_plus_one_latched_close` pins the bound the retention is acceptable because of. |
| **A record that arrives whole is scanned where it lies rather than copied** | `io_framing.rs`. `a_run_of_whole_records_copies_nothing` is the claim, and it asserts the reverted figure beside it — the same records cut in two cost their full payload, which is what the whole-record count was before the fast path existed. The three conditions that make the fast path sound each have a case: `the_tail_of_a_record_is_not_scanned_as_though_it_were_the_record` fails if the retention buffer's emptiness is dropped from the test, `a_record_is_scanned_to_its_declared_length_and_no_further` fails if the scan is handed the rest of the inbound slice instead of the record's own payload, and `a_close_record_cut_anywhere_decodes_as_the_whole_one_does` fails if the reassembling path stops agreeing with the scanning one. The last is asserted at *every* split point of a close record and one byte per read, not at a chosen one, because which of the two paths a record takes is decided by where the cut falls. |
| **An encoded close is one dwnx itself accepts** | `io_close_codec.rs`, `an_encoded_close_is_accepted_by_dwnx`, which feeds the encoder's output to a real connection and expects `ReadOutcome::PeerClosed`. Round-tripping through this crate's own decoder would prove only that the two halves agree with each other. `dwnx_accepts_a_close_that_is_not_the_first_frame_in_its_record` and `dwnx_accepts_a_close_behind_padding` put another frame in front of it, which is the layout the scan exists for. |
| **The three ways a byte stream can stop are distinguishable** | `io_lifecycle.rs`: `a_failing_byte_stream_ends_the_connection`, `a_byte_stream_that_ends_between_records_reports_the_end_of_the_stream`, and `a_byte_stream_that_ends_mid_record_reports_a_truncated_record`. The buffered error and truncation cases begin with retained output: truncation completion drains it, while a persistently broken transport returns an explicit second `ByteStream` error and releases the bounded buffer on drop rather than silently pretending delivery. `an_orderly_inbound_end_does_not_strand_retained_output` covers clean EOF, and the local-close and finish tests also begin with retained sub-ceiling output. |
| **Read-ahead is bounded by delivered-but-uncredited bytes** | `io_scheduling.rs`, `a_caller_that_credits_nothing_stops_the_layer_reading_ahead`. The caller drains every event the instant it is offered and credits nothing, which is what makes it a test of the bound rather than of the queue: a layer measuring queue depth would read zero forever and keep pulling. It asserts delivery stops at the allowance *and* has stopped growing by the halfway point, so a bound that merely lagged would not pass. |
| **Only connection-level credit adjusts that bound** | `io_scheduling.rs`, `crediting_each_byte_twice_does_not_buy_twice_the_read_ahead`. Every consumed byte is credited twice, naming the stream and then the connection, exactly as the HTTP/3 layer above does. Counting both makes each consumed byte buy two bytes of read-ahead, and in the general case that does not fail at all — it grows until something else runs out. The test also asserts the budget was actually exhausted, so a run that never reached the bound cannot pass by accident. |
| **A wait is a wait, not a self-wake** | `io_scheduling.rs`, `a_blocked_open_parks_rather_than_waking_itself` and `an_idle_connection_is_not_woken_until_its_byte_stream_reports_readiness`, which count wakeups rather than checking eventual answers. A self-wake returns the right answer eventually while burning a core, and every functional test in this suite passes with one in place. `an_open_blocked_by_the_peers_limit_completes_once_the_limit_is_raised` and `a_credit_exhausted_write_parks_and_is_woken_by_the_extension` pin the other half: the wait ends, and it never surfaces as an error. |
| **The hidden test stream counts every read poll** | `io::testing::tests::the_read_log_counts_pending_successful_and_failing_polls` proves pending, successful, and failing reads all enter the count and that a measured window can clear it. QMux/H3 uses that structural seam together with the debug-only pump counter; neither instrument is part of the supported API or release benchmark. |
| **The seam needs no `Send`, and its error still boxes** | `io_seam.rs`, `the_seam_needs_no_send_and_its_error_still_boxes`. Two claims that pull in opposite directions: a byte stream built on `Rc` is accepted, and its error type still satisfies the bound the HTTP/3 abstraction imposes on any transport. Either alone is easy; the pair is the constraint. |
| **One test body runs over both implementations of the seam** | `io_tokio.rs` runs the exchange bodies from `io_harness/` over a loopback TCP socket, and `io_transfer.rs`'s `the_shared_exchange_bodies_run_over_the_in_memory_pair` runs the same ones in memory. Two similar bodies would prove nothing about the seam; one body is what makes "not shaped around either implementation" evidence. |
| **A connection configuring nothing transfers data** | `io_lifecycle.rs`, `a_connection_built_from_the_defaults_completes_a_transfer`, which sets no limits at all. The state machine's own defaults are all zero by faithful reproduction of dwnx, so a layer that inherited them would build a connection that can open nothing and would fail by hanging. This is the test that catches that, and it only works because it configures nothing. |
| **The layer establishes nothing** | `io_lifecycle.rs`, `the_crate_offers_no_way_to_establish_a_byte_stream`, alongside `a_connection_is_created_in_each_role_from_an_established_stream`. The scope claim, asked as an absence and a presence together, because either alone is satisfied by a crate that does the wrong one. |

## Enforced about the crate's structure

In `crates/ngnet-qmux/tests/invariants.rs`, which reads the crate's own source and manifest.
These are not the questions `tests/ngnet-workspace-tests` asks: those assert what the resolved
dependency graph *contains*, and these assert what the crate *declares*.

| Property | Why it is asked this way |
| --- | --- |
| **`unsafe` appears only in the modules `lib.rs` grants it to, and every grant is used** | The compiler already rejects a stray `unsafe`, because of the crate-level `#![deny(unsafe_code)]`. What it cannot express is which modules may carry the `#[allow]` that silences it, or that a grant nothing needs has been left behind. The expected list is named explicitly as well as derived, since both could otherwise grow together. |
| **The asynchronous layer contains no `unsafe`, and grants itself none** | The layer is declared in `lib.rs` with no allowance, so the crate-level deny is what enforces it — this is the compiler-enforced form of the claim, not a grep standing in for one. The test guards the enforcement rather than the property: an `#[allow(unsafe_code)]` inside the subtree is exactly how it would be lost. |
| **Nothing outside the layer names an async facility** | `--no-default-features` is meant to be the state machine as it existed before the layer, so a `Waker` or an `async fn` outside `src/io/` would make that false while everything still compiled. |
| **The layer names no executor, spawner or timer** | It is allowed to be asynchronous; that is what it is for. It is not allowed to bring a runtime, because the caller keeps that choice. |
| **The manifest declares one non-optional dependency, gates every optional one behind `dep:`, and takes no dev-dependencies** | An optional dependency no feature names is still built whenever anything in the workspace enables it, which would make the claim true of the manifest and false of the artefact. |
| **`default = ["io"]`, `io = []`, and `tokio` implies `io` and `dep:tokio`** | The feature table is the whole of "the layer is on by default and the runtime is not" as a caller experiences it, and it is a single line away from being silently untrue. |
| **A caller never needs `unsafe`** | The tests are the crate's own callers, including the one that implements the byte-stream seam — which is the new way a caller extends this crate, and the place a `Send` bound or a raw pointer would have forced `unsafe` on them. |

## Enforced about the workspace

In `tests/ngnet-workspace-tests/`.

| Property | Why it is asked this way |
| --- | --- |
| **`ngnet-qmux` has exactly one dependency, and it is its bindings** | `dependency_graph.rs`, asked with `--no-default-features` as the HTTP/3 equivalent is, now that the asynchronous layer sits behind a default-on `io` feature. Counting alone would pass for any single dependency, so the name is checked too. |
| **The default build reaches no runtime either** | `dependency_graph.rs`. The claim that makes the seam a seam: enabling the asynchronous layer adds code and no dependencies. Asked with default features on, because that is what a caller gets by naming the crate and where feature unification could go wrong. |
| **The `tokio` feature is what reaches tokio** | `dependency_graph.rs`. The positive half, and it needs asking separately: every neighbouring check is an absence, and a feature that had quietly stopped enabling anything would satisfy all of them. Only the direct dependencies are pinned, so tokio's own graph stays tokio's business. |
| **QMux reaches no other protocol stack, TLS, or runtime** | `dependency_graph.rs`. The names invite confusion, since QMux comes from the ngtcp2 authors and reuses QUIC's frame encoding, but the two share no code here. |
| **Nothing established reaches QMux** | `dependency_graph.rs`. The reverse direction, and it needs asking separately. Both crates are unpublished and track an unratified draft, so anything depending on them inherits that churn. |
| **No QMux binary links OpenSSL** | `linkage.rs`, via `readelf`. A native library arrives through link flags a build script emits, which no manifest inspection or `cargo tree` check can see. Unconditional here, unlike the QUIC equivalent that needs a feature matrix, because QMux has no TLS backend to turn on. |

## Enforced about the build

| Property | Where |
| --- | --- |
| **A missing submodule fails with a message naming it** | `crates/ngnet-qmux-sys/build.rs` panics with the `git submodule update` command and a pointer to `just submodules`, rather than letting the C compiler report a missing header. `just submodules` checks out `deps/dwnx`, so the advice is true. |
| **The vendored version is pinned** | `crates/ngnet-qmux-sys/tests/smoke.rs` compares `DWNX_VERSION` against the version the build script substitutes. dwnx is pre-release and has never been tagged, so this pins the placeholder; the point is that a submodule bump which changes it is noticed. |
